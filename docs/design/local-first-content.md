# Local-First Content: Fossilized Content Artifacts

**Status:** User-approved — Merged (PR #2628, 2026-08-06); slice 1 in progress
**Author:** Architect
**Date:** 2026-08-06
**Priority:** P1
**Prior work:** #2624 (umbrella, Rev 3), #1393, #2626, #2625, #1073, #1741 (splitter-version design, superseded), `reports/faust_2229_investigation_2026_04_25.md`

This doc covers the architecture agreed in #2624 and specifies **slice 1** (artifact format + freeze/ingest scripts + the `get_chapters` interface) in implementable detail. Slices 2–7 are sketched only where their requirements constrain slice 1.

## Problem

Chapter boundaries are computed at request time by `services.book_chapters.split_with_html_preference` and cached only in process memory. Nothing durable stores them. Yet two kinds of durable data are keyed to `chapter_index`:

- `translations` — `PRIMARY KEY (book_id, chapter_index, target_language)`
- `annotations` — `UNIQUE (user_id, book_id, chapter_index, sentence_text)`

Every translation and annotation is therefore anchored to the output of whatever splitter build is currently running. Change the splitter and the anchors silently point at the wrong chapters. This is not hypothetical:

- Faust #2229 held translations keyed to a pre-#1055 27-chapter split; the post-#1055 splitter produces 28 chapters, misaligning everything from index 3 onward (`reports/faust_2229_investigation_2026_04_25.md`).
- Migrations `029` and `030` exist solely to delete shifted cache rows for hardcoded book ids.
- `_background_fetch_epub` calls `delete_translations_for_book` (#1556) — translations are destroyed on purpose because the system knows their anchors can't survive a source switch.
- Three alignment-checker scripts (`check_translation_alignment.py`, `translation_alignment_detectors.py`, `translation_alignment_overrides.py`) were built to *detect* drift rather than remove its cause.
- The `splitter_version` design (#1741) that was supposed to manage this drift merged as a doc in April and was never implemented. Zero code references exist.

Separately, translations generated by the live app sat DB-only for four months (116 chapters, exported 2026-08-06 in #2626) because the running app and the committed files are two write paths with no reconciliation.

## Decision (from #2624, owner-approved)

**The split becomes data, not a computation.** Per book, one committed artifact under `data/books/` holds source text structure (frozen chapter split) and translations together. The database becomes a cache populated from artifacts; the splitter demotes to a build-time tool.

- **Fossilization is progressive** — a book freezes when it first acquires something that must stay aligned (translation or annotation). Unfrozen books keep using the runtime splitter.
- **Fossilization is a one-way door per book** — the freeze must be preceded by a real audit.
- **Translation becomes one-way** (pipeline → artifact → DB); live translation is removed in slice 4, not here.

## Goals (slice 1)

1. Define the artifact schema for `data/books/book_<id>.json`.
2. `freeze_book.py`: split → audit checks → merge existing translations → write artifact.
3. `ingest_book.py`: artifact → DB, verifying `content_sha256`, touching only content tables.
4. New DB tables so frozen chapters are served from storage, not recomputation.
5. A single resolver `get_chapters(book_id)` that hides frozen-vs-runtime, so slice 7 is a deletion.
6. Pilot: freeze Faust #2229 as-is (its split is owner-audited), migrating `data/translations/book_2229_zh.json` into the artifact.

## Non-goals (slice 1)

- Removing live translation paths (slice 4) or the upload path (slice 5).
- The full content-aware audit gate (slice 3) — slice 1 ships only the mechanical pre-filter plus an explicit attestation flag.
- Freezing the other 14 translated books (progressive, after slice 3).
- User-data export / full rebuild script (slice 2).
- Any frontend change. The reader's request/response shapes are untouched.

## Artifact format

Path: `data/books/book_<id>.json`. One file per fossilized book, committed. UTF-8, `ensure_ascii=False`, `indent=2` (diffable, like the existing translation exports).

```jsonc
{
  "schema_version": 1,
  "book_id": 2229,
  "meta": {                          // enough to recreate the books row
    "title": "Faust: Der Tragödie erster Teil",
    "authors": ["Goethe, Johann Wolfgang von"],
    "languages": ["de"],
    "subjects": ["..."],
    "cover": "https://...",
    "download_count": 12345
  },
  "split": {
    "splitter": "html_preference",   // resolver used at freeze time
    "chapter_source": "epub",        // "epub" | "text" (from get_chapter_source)
    "frozen_at": "2026-08-06",
    "audited_by": "alfmunny",
    "content_sha256": "<hex>"
  },
  "chapters": [
    { "index": 0, "title": "Zueignung", "paragraphs": ["Ihr naht euch wieder…", "…"] }
  ],
  "translations": {
    "zh": {
      "generated_at": "2026-08-06T00:00:00+00:00",
      "provider": "claude-code",
      "model": "claude-opus-4-7",
      "chapters": [
        { "index": 0, "title_translation": "献辞", "paragraphs": ["…"] }
      ]
    }
  }
}
```

Notes on the shape:

- **Paragraphs, not text.** Paragraphs are the alignment unit everywhere (translations store paragraph arrays; the audit compares per-paragraph). A chapter's serving text is reconstructed as `"\n\n".join(paragraphs)`. This round-trips: the splitter's `Chapter.text` is split on blank lines exactly the way `big_translate/driver.py` already does (`split("\n\n")`, drop blanks), and the frontend re-splits on `/\n\n+/`. Internal single `\n` line breaks (verse, speaker cues) are preserved inside paragraph strings, as in the existing exports.
- **`translations.<lang>.chapters[].index` refers to `chapters[].index`** in the same file. Source and translation share one index in one file; they cannot drift apart.
- **Per-language provenance lives at the language level** (`provider`, `model`, `generated_at`), matching reality (a language is translated in one campaign). If a later re-translation mixes providers per chapter, a chapter-level `provider` override may be added then — not speculatively now.
- `meta` mirrors the `books` columns needed by `ingest`/`rebuild` so a fossilized book's row is recreatable without a Gutenberg fetch. `books.text` is *not* included: frozen books are served from chapters, and the raw text is re-fetchable by id (per #2624 Q1, the durable artifact of book *text* is the Gutenberg ID).

### `content_sha256`

Computed over the canonical serialization of the chapters array only:

```python
canonical = json.dumps(
    [{"index": c["index"], "title": c["title"], "paragraphs": c["paragraphs"]}
     for c in chapters],
    ensure_ascii=False, sort_keys=True, separators=(",", ":"))
sha = hashlib.sha256(canonical.encode("utf-8")).hexdigest()
```

Written by `freeze_book.py`; recomputed and compared by `ingest_book.py`, which **aborts loudly on mismatch**. This catches hand-edits to a frozen split (which would silently shift anchors) while leaving `meta` and `translations` freely editable — translations can be regenerated; the split cannot.

## Database changes — migration `040_book_freeze.sql`

Two new content tables. Both additive; no cleanup step needed (migration policy: constraints on *new* tables need no data cleanup).

```sql
CREATE TABLE book_freeze (
    book_id        INTEGER PRIMARY KEY REFERENCES books(id) ON DELETE CASCADE,
    splitter       TEXT NOT NULL,
    chapter_source TEXT NOT NULL,
    frozen_at      TEXT NOT NULL,
    audited_by     TEXT NOT NULL,
    content_sha256 TEXT NOT NULL
);

CREATE TABLE book_chapters (
    book_id       INTEGER NOT NULL REFERENCES books(id) ON DELETE CASCADE,
    chapter_index INTEGER NOT NULL,
    title         TEXT NOT NULL DEFAULT '',
    text          TEXT NOT NULL,
    PRIMARY KEY (book_id, chapter_index)
);
```

- `book_chapters.text` stores the reconstructed serving text (`"\n\n".join(paragraphs)`) so the read path produces `Chapter(title, text)` with zero transformation. Paragraph arrays remain the artifact's concern.
- A row in `book_freeze` is the *frozen* flag. No `books` column is added — avoids a table rewrite and keeps freeze metadata in one place.
- These are **content tables**: `rebuild.py` (slice 2) may wipe and repopulate them from `data/`; they hold nothing user-derived.
- Distinct from `user_book_chapters` on purpose: that table is upload-flow-specific (drafts, FTS triggers) and is scheduled for deletion in slice 5. Reusing it would couple slice 1 to slice 5's teardown.

Tests in `test_migrations.py` per convention: table creation, PK/FK enforcement, idempotent re-run.

## The resolver: `get_chapters(book_id)`

New public entry point in `services/book_chapters.py`:

```python
async def get_chapters(book_id: int) -> list[Chapter]
```

Resolution order:

1. **Frozen:** `book_freeze` row exists → read `book_chapters` rows ordered by `chapter_index` → `list[Chapter]`. Pure DB read. No splitter import, no EPUB touch, **no `_background_fetch_epub`** — the background fetch's `delete_translations_for_book` side-effect must never fire for a frozen book (it would destroy pipeline-generated translations).
2. **Upload:** existing `user_book_chapters` branch, unchanged (until slice 5 removes it).
3. **Runtime fallback:** existing behaviour — load `books.text` internally, then `split_with_html_preference` semantics (EPUB preferred, plain-text fallback, background EPUB fetch).

The existing in-memory `_chapter_cache` / `_split_locks` wrap all three branches unchanged; `clear_cache(book_id)` still invalidates. `get_chapter_source(book_id)` does **not** grow a `"frozen"` value — for frozen books it returns `book_freeze.chapter_source` (`"epub"` or `"text"`, recorded at freeze time), so the frontend `ChapterSource` type and reader behaviour are untouched.

### Call-site migration

`split_with_html_preference(book_id, text)` currently has ~25 runtime call sites across 8 modules (`routers/books.py` ×8, `admin.py` ×3, `ai.py` ×5, `annotations.py`, `insights.py`, `user.py`, `vocabulary.py`, `services/translation_queue.py` ×3). Roughly half call it only for `len(chapters)` bounds checks. All of them already have or can drop the `text` argument — `get_chapters(book_id)` loads text itself on the fallback path (one extra cached DB read; the row is already loaded at most sites, but keeping the signature to `book_id` only is what makes slice 7 a deletion).

Mechanical rule: every runtime call `await split_with_html_preference(book_id, text)` becomes `await get_chapters(book_id)`; `split_with_html_preference` becomes internal to `book_chapters.py` (renamed `_split_uncached` or similar) and is no longer imported by routers/services. Scripts (`big_translate/driver.py`, `save_batch.py`, alignment checkers) keep using splitter APIs directly — they are build-time tools, which is where the splitter now belongs.

After slice 7 (every book frozen), branch 3 and the splitter import are deleted and serving is a pure DB read.

## `freeze_book.py`

`backend/scripts/freeze_book.py` (top-level, not under `big_translate/`, so `generate_docs.py`'s non-recursive glob picks up its docstring). 

```
python -m scripts.freeze_book --book-id 2229 --audited-by alfmunny [--dry-run] [--force]
```

Steps:

1. Load book row + chapters via the same resolver the reader uses (`get_chapters`), guaranteeing the frozen split is byte-identical to what the owner audited in the reader. Refuse if the book is already frozen (one-way door; a deliberate re-freeze requires `--force` and prints a warning that existing annotations/translations anchors must be re-audited).
2. Split each chapter's text into paragraphs (`\n\n`, drop blanks) — same rule as `big_translate/driver.py`.
3. **Mechanical audit pre-filter** (the `big_translate` README TODO, finally implemented): flag chapters with paragraph count < 2, text length < 100 chars, or > 50 % uppercase — the TOC-fragment / ISBN-notice / stray-heading signatures. Findings print as a report. Any finding blocks the write unless `--force` is given; `--force` records nothing silently — the findings are printed either way. (Slice 3 extends this into the content-aware gate; the flag semantics stay.)
4. **Merge existing translations** for this book id from both legacy conventions:
   - `data/translations/book_<id>_<lang>.json` (object-wrapped, exported from DB 2026-08-06 — authoritative on conflict)
   - `backend/data/translations/<id>_<lang>.json` (bare-array per-save backups — fills gaps; e.g. book 345 has 30 entries here vs 4 in the main export)
   Union by `chapter_index`; drop entries whose `chapter_index >= len(chapters)`; carry `provider`/`model`/`title_translation` when present. A translation entry whose paragraph count mismatches its source chapter is included but reported — the alignment checker, not the freeze script, judges those (its DB-based read path gains an artifact-based mode in slice 3).
5. Compute `content_sha256`, write `data/books/book_<id>.json`, print a summary (chapter count, per-language coverage, audit findings).

`--audited-by` is **required**. It is an attestation, not metadata decoration: the human (or agent session) named has read the chapter list against the source. Freezing a bad split is worse than not freezing.

`--dry-run` performs everything except the write.

## `ingest_book.py`

`backend/scripts/ingest_book.py`:

```
python -m scripts.ingest_book --book-id 2229 [--all] [--db-path ...]
```

Steps, per book, in one transaction:

1. Read `data/books/book_<id>.json`; validate `schema_version` and required keys.
2. Recompute `content_sha256` over the chapters array; **abort on mismatch** (exit 2, nothing written).
3. Upsert the `books` row from `meta` (leaving `text` as-is if the row exists, `''` if created — frozen books don't serve from `text`).
4. Replace `book_chapters` rows and the `book_freeze` row for this book.
5. Replace `translations` rows for each language in the artifact (`INSERT OR REPLACE` on the existing PK). Languages present in the DB but absent from the artifact are left alone until slice 4 removes the live write path; after slice 4, ingest becomes the only writer and this becomes a full per-book replace.
6. `clear_cache(book_id)` equivalent is unnecessary (separate process), but the script prints a reminder that a running server holds a process-local cache; in production the deploy restart clears it.

Touches **only** content tables (`books`, `book_chapters`, `book_freeze`, `translations`). Never `annotations`, `vocabulary`, `reading_history`, or any user table — this is the invariant slice 2's `rebuild.py` inherits.

## Migration-period behaviour (slices 1–7)

- The reader serves frozen books from `book_chapters` and unfrozen books via the runtime splitter, behind one interface. No caller branches; no frontend change; the API response shape is identical.
- `data/translations/*.json` and `backend/data/translations/*.json` remain in place until their books are frozen; each freeze absorbs that book's files, after which they are deleted in the same PR. When the last one is absorbed, the two legacy directories and `save_translation.py`'s backup path go away (folded into slice 4/6 cleanup).
- Until slice 4 lands, live translation can still write `translations` rows for frozen books that the artifact doesn't have. That divergence is bounded (export via `finalize.export_book` still works) and closes permanently with slice 4.
- **Hazard closed by design:** for frozen books the resolver never enters the EPUB-fetch branch, so #1556's `delete_translations_for_book` side-effect cannot destroy pipeline translations.
- Slice 6 (#1393's 95-book loop) stays blocked until slices 1–3 land, per #2624 — resuming earlier would anchor 95 books to a split we are changing.

## Test plan

Migration (`test_migrations.py`):
- `test_migration_040_book_freeze_tables_created` — tables exist, PK/FK enforced, re-run idempotent.

`freeze_book.py` (`test_freeze_book_script.py`):
- Artifact round-trip: freeze a seeded book → file matches schema, sha verifies.
- Paragraph reconstruction: `"\n\n".join(paragraphs)` reproduces `Chapter.text` for prose and verse (internal `\n` preserved).
- Mechanical audit: a seeded TOC-fragment chapter (< 100 chars) blocks the write; `--force` proceeds and still reports.
- Translation merge: Convention A + B union, A wins on conflict; out-of-range `chapter_index` dropped and reported.

`ingest_book.py` (`test_ingest_book_script.py`):
- Happy path: artifact → `books`/`book_chapters`/`book_freeze`/`translations` rows correct.
- Tampered chapters → sha mismatch → exit 2, nothing written (transaction intact).
- Re-ingest idempotent; existing DB-only translation language left alone.
- Never touches user tables (seed an annotation, assert untouched).

`get_chapters` (`test_book_chapters.py` additions):
- Frozen book served from `book_chapters`, splitter never invoked (monkeypatch-assert), background EPUB fetch never fired.
- Unfrozen book falls through to existing behaviour (existing tests keep passing).
- Cache + `clear_cache` behaviour across both branches.
- Bounds-check call sites behave identically (spot-check via router tests: annotations, progress, vocabulary).

Full suites (`pytest` from `backend/`, frontend Jest) must pass; no frontend changes expected, so its suite is a regression guard only.

## Rollback

- Migration 040 is additive; rolling back is dropping two empty-by-default tables.
- Un-freezing a book (delete its `book_freeze` + `book_chapters` rows) restores runtime-splitter behaviour exactly. This is safe **only before** annotations/translations accumulate against the frozen split — which is the point of the one-way-door rule, not a technical restriction.
- Artifacts are committed files; git revert restores any prior state.

## Open questions

1. **Q4 from #2624 — partial orphans** (King in Yellow 36/44, Gatsby 4/9, Crime & Punishment 8/40 + 30 more under Convention B, Dracula 4/30 + 30 under B, Hamlet 1/21, Room with a View 1/21). Recommendation: **keep** — they cost real tokens and are aligned to the current split; the freeze absorbs them and slice 6's pipeline fills the gaps. Discarding buys nothing.
2. **Splitter identifier granularity.** `split.splitter` records the resolver family (`html_preference`) + `chapter_source`. Recording a git SHA of the splitter would be more precise but misleading after the splitter moves/changes — under fossilization the output is authoritative, not the producer. Proposed: keep the coarse label.
3. **Artifact size ceiling.** City of God (133 chapters) and Moby Dick (138) with translations will produce ~2–5 MB artifacts; 127 books eventually ≈ tens of MB in git. #2624 accepts this ("progressive" growth, owner confirmed `data/` location). Flagging only in case repo-size policy changes; no action proposed.
